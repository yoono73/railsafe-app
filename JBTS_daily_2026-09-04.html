(1) 메시지 종류

기호메시지판단 근거
㉠GetRequest인스턴스 .0까지 지정된 특정 객체 1개 조회 → 관리자→에이전트, 161

㉤SetRequestMIB 객체 값을 변경(쓰기), 161

(2) 4번 패킷만 포트가 다른 이유
1·3·5번은 관리자 → 에이전트 방향의 요청이므로 에이전트의 수신 포트 UDP 161을 사용한다. 반면 4번은 링크 다운이라는 이벤트를 에이전트 → 관리자 방향으로 자발 통보하는 Trap이므로, 관리자(NMS)가 Trap 수신용으로 대기하는 UDP 162로 전송된다. 즉 Trap만 방향과 포트가 반대이며, 5가지 메시지 중 유일한 에이전트→관리자 단방향 메시지이다.

(3) 폴링 부하 계산

① 1주기당 OID 수 = 200대 × 12개 = 2,400 OID 1주기당 메시지 수 = 2,400 × 2 = 4,800 메시지 초당 메시지 수 = 4,800 ÷ 300초 = 16 msg/s ② 1주기당 트래픽 = 2,400쌍 × 180 byte = 432,000 byte 초당 트래픽 = 432,000 ÷ 300 = 1,440 byte/s 대역폭 = 1,440 × 8 = 11,520 bps ≒ 11.52 kbps
⚠ 함정 ① 메시지 수와 "쌍(pair)" 수를 혼동 — 크기 180 byte는 요청+응답 1쌍 기준이므로 2,400쌍에 곱해야 한다(4,800을 곱하면 2배 오답).
② byte → bit 환산(×8) 누락.
③ Trap 포트를 161로 쓰는 실수 — 폴링 161 / Trap 162.
🔑 SNMP 핵심 — 5메시지: GetRequest·GetNextRequest·SetRequest·GetResponse(161) / Trap(162). 전송계층 UDP(오버헤드 최소화, 연결설정 없이 장애 중에도 전송 가능 → 신뢰성은 관리자의 타임아웃·재시도로 보완), 애플리케이션 계층 프로토콜. NMS 4요소 = 관리스테이션 + 에이전트 + MIB + SNMP.
